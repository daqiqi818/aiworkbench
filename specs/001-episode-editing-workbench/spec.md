# Feature Specification: Multi-Episode Editing Workbench

**Feature Branch**: `001-episode-editing-workbench`

**Created**: 2026-10-29

**Status**: Draft

**Input**: User description: "在当前工程基础上，将 OpenMontage 的多剧集剪辑功能移植到该项目，形成一个本地工作台，让用户能够在一个独立菜单内新建，审核剪辑任务，并查看其状态"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新建多剧集剪辑任务 (Priority: P1)

创作者从独立的多剧集剪辑工作台进入新建流程，为一部短剧选择至少两集素材，填写剪辑目标、目标受众、交付偏好和内容限制，并提交一个可审核的剪辑任务。

**Why this priority**: 没有结构化的新建入口，创作者无法把跨剧集的叙事素材转化为可管理的剪辑任务。

**Independent Test**: 使用两集已授权素材，创作者可在一个工作台内完成必填信息、提交任务，并在任务列表中找到新建记录。

**Acceptance Scenarios**:

1. **Given** 创作者打开独立的多剧集剪辑菜单，**When** 创建任务并选择至少两集素材，**Then** 系统创建一个属于该短剧的跨剧集剪辑任务。
2. **Given** 创作者填写剪辑目标、目标受众、交付偏好和剧透限制，**When** 提交任务，**Then** 系统保留这些信息以及剧集顺序和每集素材选择。
3. **Given** 必填信息缺失、只有一集被纳入，或素材未确认可用，**When** 创作者尝试提交，**Then** 系统指出具体问题且不创建含糊的任务。

---

### User Story 2 - 审核剪辑方案 (Priority: P2)

创作者在任务开始实际剪辑前审核剪辑方案，了解叙事钩子、情绪走向、剧集覆盖范围、交付定义、预估成本和素材限制，并可批准、请求修改或取消。

**Why this priority**: 跨剧集剪辑会影响故事揭示和商业投放，创作者必须在不可逆或付费工作开始前掌握并批准创意方向。

**Independent Test**: 对一个已提交任务，创作者可完整查看方案并完成批准、请求修改或取消中的任一操作；未批准时任务不会进入制作。

**Acceptance Scenarios**:

1. **Given** 一个完整任务正在等待审核，**When** 创作者打开任务，**Then** 系统展示剪辑方案、纳入和排除的剧集、内容限制、交付偏好与已知限制。
2. **Given** 任务正在等待审核，**When** 创作者请求修改并提供说明，**Then** 系统记录修改意见，任务返回待方案状态，并保留此前的决策记录。
3. **Given** 任务尚未得到批准，**When** 创作者查看其状态，**Then** 系统明确显示需要审核，且不会启动实际剪辑或最终交付。

---

### User Story 3 - 跟踪任务与获取交付物 (Priority: P3)

创作者从同一工作台查看所有任务，按状态定位目标任务，理解当前阶段、下一步行动或阻塞原因，并在完成后取得成片及对应的剪辑摘要。

**Why this priority**: 本地工作台必须提供可操作的任务可见性，而非让创作者依赖不可解释的后台处理。

**Independent Test**: 对处于待审核、处理中、受阻、已完成或已取消状态的准备数据，创作者可以看到一致的状态、下一步或阻塞信息，并从已完成任务打开其交付物摘要。

**Acceptance Scenarios**:

1. **Given** 创作者有多个多剧集剪辑任务，**When** 打开工作台，**Then** 系统列出每项任务的短剧名称、当前状态、当前阶段和最近更新时间。
2. **Given** 一个已批准任务推进或受阻，**When** 创作者打开该任务，**Then** 系统显示当前阶段、下一步行动；受阻时还显示失败原因、影响、可选路径和建议。
3. **Given** 一个任务已完成，**When** 创作者打开该任务，**Then** 系统提供最终成片位置及可检索的剪辑摘要，其中包含批准过的创意方向和剧集覆盖范围。

### Edge Cases

- 某集已被列入但没有可用素材时，系统必须要求创作者补充素材、排除该集并说明原因，或停止提交。
- 所选素材与剧透限制冲突时，系统必须在审核前标明冲突，并不得静默改变已批准的限制。
- 素材方向、时长、质量或使用权不一致时，方案必须说明对交付的影响。
- 被批准的任务中断时，系统必须显示最后完成的阶段；只有有效的后续步骤可以继续。
- 创作者取消任务后，系统必须保留任务和决策记录，且不得把它作为可继续处理的任务展示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在主产品中提供一个名称清晰、独立可进入的多剧集剪辑工作台。
- **FR-002**: 系统 MUST 允许创作者从工作台新建一个属于单部短剧的跨剧集剪辑任务。
- **FR-003**: 系统 MUST 在提交前收集短剧名称、剪辑目标、目标受众、交付偏好、剧透限制、剧集顺序，以及每集的素材或素材引用。
- **FR-004**: 系统 MUST 要求每项任务纳入至少两集，并保留创作者给出的剧集顺序、每集纳入或排除决定，以及排除原因。
- **FR-005**: 系统 MUST 阻止未确认有使用权限的素材进入任务，并向创作者指出该素材。
- **FR-006**: 系统 MUST 为完整任务生成可审核的剪辑方案，方案包含叙事钩子、情绪走向、剧集覆盖、交付定义、预估成本和已知素材限制。
- **FR-007**: 系统 MUST 要求创作者显式批准剪辑方案，才能开始实际剪辑或生成最终交付物。
- **FR-008**: 系统 MUST 允许创作者请求修改或取消待审核任务，并保留方案、修改意见和批准决定的历史记录。
- **FR-009**: 系统 MUST 在工作台和任务详情中呈现任务状态、当前阶段、下一步行动及最近更新时间。
- **FR-010**: 系统 MUST 对受阻任务展示已尝试的操作、失败原因、交付影响、可选路径和建议操作。
- **FR-011**: 系统 MUST 为已完成任务保留最终交付物位置和剪辑摘要，摘要包含已批准的创意方向及纳入、排除的剧集。
- **FR-012**: 首版 MUST 限于每个任务对应一部短剧和一个最终剪辑交付物；单集剪辑、批量变体、发布、翻译配音和非短剧视频不在范围内。

### Key Entities *(include if feature involves data)*

- **短剧剪辑项目**: 一部短剧及其剪辑目标、目标受众、内容限制和交付偏好。
- **剧集素材集**: 有序的剧集摘要、每集素材或引用、使用权限状态、限制条件和纳入决定。
- **剪辑任务**: 连接短剧剪辑项目、素材集和生命周期状态的本地工作项。
- **剪辑方案**: 供审核的创意计划，包括叙事钩子、情绪走向、剧集覆盖、交付定义、预估和审核状态。
- **任务决策记录**: 对方案的批准、修改、取消和阻塞处置的可追溯记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对含 2 至 12 集已准备素材的短剧，创作者可在 10 分钟内完成并提交剪辑任务，且无需离开工作台。
- **SC-002**: 100% 的已提交任务在审核前明确列出纳入、排除的剧集及剧透限制。
- **SC-003**: 100% 缺少批准、可用素材或使用权确认的任务显示可操作的阻塞状态，而非静默改变创意方向。
- **SC-004**: 在验收测试中，至少 90% 的创作者能使用准备好的跨剧集素材包在首次尝试完成新建、审核和批准流程。
- **SC-005**: 100% 的已完成任务提供最终交付物及可检索的剪辑摘要。
- **SC-006**: 创作者可在 30 秒内从工作台的任务列表识别任一任务的当前状态和下一步行动。

## Assumptions

- 使用者是在本地工作台中管理短剧素材和剪辑任务的创作者，首版不新增多用户协作流程。
- 创作者仅提交拥有剪辑和推广使用权限的素材；工作台记录其确认结果。
- OpenMontage 的多剧集短剧剪辑能力是该功能的业务参考，但首版只向用户暴露本规格中的本地工作台流程。
- 每个准备好的短剧项目至少包含两集的简要剧情信息和足以支持连贯剪辑的素材或引用。
- 首版服务一个主剪辑交付物，不承担批量营销变体或直接发布到内容平台。

## Amendment: Native Compose Failure Integrity

- **FR-027**: OpenMontage Runner 写入的 `render_report` MUST 满足随仓库发布的 OpenMontage schema；扩展的剪辑说明 MUST 放在 schema 允许的 `metadata.editorial_report` 中。
- **FR-028**: 任一原生阶段失败 MUST 在 Runner 中持久化为带机器可读错误文本的 `blocked` 状态。BeefTV 后续轮询 MUST 保持该状态和错误原因，不能将其重新投影为制作中。

## Amendment: In-Page Delivery Playback

- **FR-029**: 打开成片 MUST 使用紧凑的当前页播放窗口，并限制竖屏成片高度以避免遮挡工作台。
- **FR-030**: 关闭播放窗口时 MUST 立即暂停并卸载视频资源；关闭按钮、遮罩和 Esc 的行为必须一致。

## Amendment: Asset-Folder Episode Workflow

### Updated User Scenarios & Testing

#### User Story 4 - 管理剧集素材文件夹 (Priority: P1)

创作者在资产菜单中新建并命名文件夹，将每一集的视频素材归入对应文件夹，随后可以在资产列表中看到和使用该文件夹。

**Why this priority**: 剧集文件夹是多剧集剪辑选择素材的前提；当前新建入口无法完成这个工作，创作者不能可靠地整理剧集视频。

**Independent Test**: 创作者新建一个名称有效的文件夹，将视频素材归入该文件夹，刷新资产页面后仍可在分类列表中找到该文件夹和其中素材。

**Acceptance Scenarios**:

1. **Given** 创作者位于资产菜单，**When** 输入一个未重复的有效文件夹名称并确认，**Then** 新文件夹立即出现在分类列表中，并可作为上传或移动视频素材的目标。
2. **Given** 文件夹名称为空、超出允许长度或与现有名称重复，**When** 创作者尝试新建，**Then** 系统展示具体原因且不创建文件夹。
3. **Given** 创作者已新建剧集文件夹，**When** 刷新或重新进入资产菜单，**Then** 该文件夹及其素材归属保持可见。

#### User Story 5 - 从剧集文件夹新建剪辑任务 (Priority: P1)

创作者在独立的多剧集剪辑工作台新建任务，选择同一短剧的剧集素材文件夹。工作台识别可选剧集数量，默认选中全部剧集，允许创作者取消不需要制作的剧集，并以紧凑表单设置交付范围。

**Why this priority**: 手工输入剧集编号、摘要和素材引用既慢又容易出错；直接选择资产文件夹才能把已整理的视频素材可靠地带入任务。

**Independent Test**: 准备至少两个含视频素材的剧集文件夹后，创作者可在一个紧凑表单中选择文件夹、看到可制作剧集数、保留或取消默认选择，并成功提交任务。

**Acceptance Scenarios**:

1. **Given** 创作者打开新建多剧集剪辑任务，**When** 选择包含剧集文件夹的资产范围，**Then** 系统列出识别到的剧集文件夹和数量，且默认全部选中。
2. **Given** 识别到多个剧集文件夹，**When** 创作者取消其中一个或多个剧集，**Then** 系统只将仍选中的剧集纳入任务，并在提交前显示选中数量。
3. **Given** 创作者至少选择两个含素材的剧集文件夹，**When** 填写短剧名称、画幅、时长范围、语言、投放平台和剧透限制后提交，**Then** 系统创建一个可审核的跨剧集剪辑任务，并保留所选文件夹的顺序与素材归属。
4. **Given** 已选剧集不足两集或某个选中文件夹没有可用视频素材，**When** 创作者尝试提交，**Then** 系统指出具体文件夹或选择问题且不创建任务。

### Updated Requirements

The following requirements supersede any conflicting earlier requirements in this specification:

- **FR-018**: 系统 MUST 允许创作者在资产菜单新建、重命名和使用个人资产文件夹；有效的新建文件夹必须在保存后可见。
- **FR-019**: 新建任务 MUST 收集短剧名称、画幅、最小时长、最大时长、语言、投放平台、剧透限制及选中的剧集文件夹；不得再要求目标受众或剪辑目标。
- **FR-020**: 系统 MUST 将可访问且含可用视频素材的资产文件夹识别为可选择剧集，并显示识别总数、每个剧集的名称、素材数量与选中状态。
- **FR-021**: 当可选择剧集首次载入时，系统 MUST 默认选中全部剧集；创作者 MUST 能逐一取消或恢复选择。
- **FR-022**: 系统 MUST 要求每项任务至少选中两集，并保留创作者选择的剧集顺序及每集对应的资产文件夹；文件夹的所有权和可用素材必须在提交时重新确认。
- **FR-023**: 最小时长 MUST 不小于 15 秒，最大时长 MUST 不大于 300 秒，且最小时长 MUST 不大于最大时长。
- **FR-024**: 语言 MUST 仅支持中文和英文；投放平台 MUST 仅支持 TikTok、Facebook、视频号和抖音。
- **FR-025**: 新建任务表单 MUST 使用紧凑布局，同时保持字段标签、验证信息、剧集数量和选择状态清晰可读。
- **FR-026**: 工作台及任务详情 MUST 呈现选中剧集数和所选剧集文件夹，并继续展示既有任务状态、当前阶段、下一步行动和最近更新时间。

### Updated Edge Cases

- 没有可选择的剧集文件夹时，工作台必须明确提示创作者先在资产菜单新建文件夹并归入视频素材。
- 文件夹名称相同、空白、过长或创建过程中发生保存失败时，系统必须保留输入并展示可操作的错误，不得伪报创建成功。
- 已选文件夹被删除、改名、转移给其他用户或其视频素材被移除时，任务创建必须拒绝失效选择并指明受影响文件夹。
- 时长下限小于 15 秒、上限大于 5 分钟，或最小时长大于最大时长时，系统必须阻止提交并标明相应范围。
- 语言或投放平台不在受支持选项中时，系统必须拒绝提交；现有任务仍可查看其历史交付信息。

### Updated Entities and Assumptions

- **资产剧集文件夹**: 创作者拥有的资产文件夹；在本功能中一个文件夹代表一个剧集，包含该集视频素材。
- **剧集选择**: 任务中一个已选资产剧集文件夹的顺序、名称、可用视频数和可用性状态。
- 当前资产文件夹为扁平结构；一个文件夹代表一个剧集，不要求在任务创建时再识别嵌套子文件夹。
- 只有归属当前创作者且包含至少一个可用视频素材的文件夹可作为剧集选择。

### Updated Success Criteria

- **SC-007**: 创作者可在 2 分钟内新建一个剧集素材文件夹并将其作为视频素材归属目标使用。
- **SC-008**: 对含 2 至 12 个已准备剧集文件夹的短剧，创作者可在 5 分钟内完成并提交剪辑任务，且无需手工输入剧集编号、摘要或素材引用。
- **SC-009**: 100% 的已提交任务明确记录所选剧集文件夹、选中剧集数、时长范围、语言和投放平台。
- **SC-010**: 100% 超出时长边界、时长范围倒置、剧集不足两集、文件夹失效或选项不受支持的提交均显示可操作的阻塞原因，且不创建任务。

## Amendment: Browser-Local Asset Folder Availability

### User Story 6 - 使用浏览器本地剧集文件夹创建任务 (Priority: P1)

创作者在浏览器本地工作台的资产菜单中创建剧集文件夹并上传视频后，进入多剧集剪辑工作台时可以选择该文件夹，不需要重新上传视频或手工重复录入素材。

**Why this priority**: 浏览器本地资产库与任务工作台必须呈现同一套可选剧集；否则已归入文件夹的视频会被错误地报告为不存在。

**Independent Test**: 在浏览器本地模式创建名为 `67906322` 的文件夹并上传视频，打开新建剪辑任务后，该文件夹显示为一个带正数视频数量、默认选中的候选剧集。

**Acceptance Scenarios**:

1. **Given** 创作者已有仅保存在浏览器本地的剧集文件夹和视频，**When** 打开新建剪辑任务，**Then** 系统同步文件夹和素材元数据，并将包含视频的文件夹列为可选剧集。
2. **Given** 浏览器本地文件夹与本地工作台中已有同名文件夹，**When** 同步发生，**Then** 系统复用同一个文件夹，不创建重复分类，并保持其中视频的归属。
3. **Given** 浏览器本地视频已被识别为任务候选，**When** 创建任务，**Then** 任务只保存素材引用和文件夹快照，不复制或重新上传视频二进制。
4. **Given** 元数据同步失败，**When** 创作者打开新建任务，**Then** 系统保留浏览器本地素材并显示可操作的同步失败原因，不把文件夹误报为没有视频。

### Updated Requirements

The following requirements supplement earlier requirements in this specification:

- **FR-027**: 浏览器本地模式 MUST 将资产文件夹及素材元数据同步到本地任务后端，以便资产菜单和多剧集工作台识别相同的剧集文件夹。
- **FR-028**: 同步 MUST 保留浏览器本地媒体二进制及其本地存储引用；不得因创建或选择剪辑任务重新上传或复制视频文件。
- **FR-029**: 同步 MUST 按当前用户和文件夹名称去重，并在同步后更新浏览器本地素材对该文件夹的引用，使后续移动、删除和任务校验使用同一文件夹标识。
- **FR-030**: 新建、上传或移动素材到浏览器本地剧集文件夹后，系统 MUST 在下一次任务候选读取前同步相关元数据；同步错误 MUST 向用户暴露，而不能静默显示空候选列表。

### Updated Edge Cases

- 历史浏览器本地文件夹的标识与本地后端标识不同时，系统必须在不丢失视频归属的前提下迁移其素材引用。
- 同步过程中存在同名后端文件夹时，系统必须复用该文件夹；不得生成重复分类。
- 本地媒体 Blob 不可读取不应导致已存在的素材元数据被删除；任务创建仍由后端对已同步的当前归属和视频状态校验。

### Updated Assumptions

4. **Given** 一个候选剧集视频仍被项目、画布、其他任务或其他业务对象引用，**When** 创作者请求同时删除剧集

5. **Given** 创作者选中两个已完成任务，**When** 确认批量删除，**Then** 系统实际接收并处理两个选中的任务
   标识，返回每项成功或失败结果；空选择、未知任务和无权任务均显示明确原因。

### Updated Requirements

- **FR-066**: 批量任务删除 MUST 将创作者实际选中的每个任务唯一标识可靠传递并由服务端逐项验证；已完成、
  已取消和受阻任务在没有其他删除阻塞条件时 MUST 可删除，且确认后任务列表必须刷新为实际结果。
- **FR-067**: 删除确认窗口 MUST 显示选中任务数量，并提供“同时删除剧集文件”复选框；该复选框 MUST 默认
  未选中，未选中时删除任务不得删除剧集视频、成片或报告资产。
- **FR-068**: 仅当创作者显式选中“同时删除剧集文件”时，系统 MAY 删除同一被删除任务纳入的剧集视频资产；
  删除范围 MUST 限于这些剧集视频，且不得包含成片、渲染报告或未纳入该任务的资产。
- **FR-069**: 请求删除剧集视频时，系统 MUST 先检查项目、画布、任务及其他业务引用；存在引用时 MUST 保留
  资产并返回引用来源。任务删除及其他无引用视频的删除结果 MUST 独立反馈，不得因单项受阻而静默回滚。
- **FR-070**: 本修订涉及删除路径的实现 MUST 在交付前完成真实浏览器端到端验证：选择两个已完成任务，分别
  验证默认删除和勾选删除剧集文件两种流程的列表、任务、源视频、成片及报告结果；不得以编译、静态阅读
  或仅接口测试替代该验证。

### Edge Cases

- 同一剧集视频被两个待删除任务共同引用时，系统必须在删除处理期间重新检查引用；只有最后一个引用被安全
  移除且不存在其他业务引用时，才可删除视频。
- 一个批量请求中某项任务已被其他操作删除、失去权限或无法删除时，其他独立任务必须继续处理，并为每项
  返回可理解结果。
- 创作者勾选“同时删除剧集文件”后，任何一个剧集视频物理删除失败时，系统不得删除其资产记录，并须报告
  文件未删除的原因。

### Assumptions

- “剧集文件”指任务纳入的 BeefTV 剧集视频资产，不包含最终成片、渲染报告、剧集文件夹本身或其他任务的
  视频资产。
- 删除任务的审计记录按照当前产品保留策略处理；此修订不要求删除用户无权读取的任何数据。

### Success Criteria

- **SC-026**: 真实浏览器验收中，选中两个已完成任务并保持文件删除选项未选时，100% 的任务删除请求实际处理
  两个任务，任务列表随即不再显示它们，且源视频、成片与报告仍可在资产库中找到。
- **SC-027**: 真实浏览器验收中，勾选文件删除选项后，100% 无引用的所选剧集视频被删除；100% 有引用的视频
  被保留并显示引用原因，且不会删除成片、报告或无关资产。

## Amendment: Delete Active Native Productions

### User Story 18 - 删除进行中的短剧剪辑任务 (Priority: P1)

创作者可以从短剧剪辑列表选择一个或多个正在制作或已批准的任务并删除。系统必须先通知该任务所属的
OpenMontage 制作停止，并在收到已停止确认后删除对应的 BeefTV 任务记录；停止失败时，任务必须保留且说明原因。

**Independent Test**: 对一个真实正在等待 OpenMontage 阶段审批的任务执行删除，确认 Runner 记录该生产为
`cancelled`，原任务从列表消失；模拟停止失败时，任务仍在列表且说明停止失败。

**Acceptance Scenarios**:

1. **Given** 创作者选中一个正在制作且关联 OpenMontage 生产的任务，**When** 确认删除，**Then** 系统先向该生产
   发出停止请求，收到停止确认后才删除任务。
2. **Given** 停止请求失败、运行器不可用或未确认停止，**When** 创作者确认删除，**Then** 系统保留该任务并展示原因，
   同一批中其他独立任务仍继续处理。
3. **Given** 一批删除同时包含进行中和已完成任务，**When** 确认删除，**Then** 每一项分别得到停止并删除成功、普通删除
   成功或保留原因；不得因单个停止失败撤销其他删除。

### Updated Requirements

- **FR-071**: 已批准或正在制作且关联 OpenMontage 生产的任务 MUST 在删除前由后端以当前所有者身份请求停止；
  仅当运行器明确返回已停止时，系统才能删除该任务记录。
- **FR-072**: 运行器不可用、停止失败、停止返回非终止状态或任务缺少安全停止通道时，系统 MUST 保留该任务并返回
  逐项机器可读原因；批量请求中的其他任务不受影响。
- **FR-073**: 进行中任务的删除 MUST 不由浏览器直接访问 OpenMontage，也不得删除 BeefTV 源视频、成片或报告，
  除非创作者同时显式选择了既有的源视频删除选项。

### Success Criteria

- **SC-028**: 真实浏览器验收中，删除一个进行中的 OpenMontage 任务时，100% 的成功删除均有对应的 Runner
  已停止记录，且任务随即从工作台列表移除。
- **SC-029**: 停止失败验收中，100% 的失败项保留任务并展示停止原因，且同批可独立删除的任务仍完成删除。
