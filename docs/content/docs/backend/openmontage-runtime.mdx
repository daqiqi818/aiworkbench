## 定位

OpenMontage 制作能力作为 BeefTV 内部运行时发布，不提供独立的公网入口。后台负责用户、资产、
任务、授权和交付展示；运行时负责保留原生 OpenMontage `cinematic` 流程、项目工作区和检查点。

首期 Runner 仅验证原生工作区、阶段顺序、检查点和多用户隔离，默认禁用供应商执行。付费供应商
或本地 GPU 工具必须在预算、能力与审批策略完成验收后才可启用。

## 源码与许可证

`third_party/openmontage/` 是 OpenMontage 的固定源码快照。来源 commit、导入排除项和本地修改记录
位于 `third_party/openmontage/UPSTREAM.md`。不允许向其中加入环境文件、凭据、虚拟环境、Node 依赖、
缓存或用户项目。

包含该运行时的 BeefTV 发布版遵守 AGPLv3-or-later。部署者必须在网络服务界面和发布材料中提供
对应源代码取得方式，并保留根目录 `LICENSE`、`NOTICE` 与 `THIRD_PARTY_NOTICES.md` 中的声明。

## 部署

`openmontage-runner` 只在 Compose 内部网络运行，不映射宿主机端口。生产部署必须设置
`OPENMONTAGE_RUNNER_TOKEN`，并使用持久工作区卷；不得使用默认开发令牌。

工作区键由用户与生产任务共同确定，路径不返回给浏览器或业务 API。任何后续任务派发、读取、
审核、取消和交付导入均必须携带并验证用户和生产身份。

## 资产边界

BeefTV 是剧集源视频和最终成片的唯一资产登记系统。Runner 创建生产时只接收 BeefTV 资源 ID，
并在实际探测或合成时通过生产级短期凭据读取对应资源；它不接收浏览器上传、宿主路径、任意 URL、
OSS 配置或永久源媒体副本。临时渲染输入在单个步骤结束后删除。

完成后 Runner 只暴露内部成片和报告流。Backend 将它们导入 BeefTV 资源库，并把成片注册为源短剧
文件夹下的视频资产；只有视频和报告均导入成功，任务才投影为完成。

## 升级

新 OpenMontage 版本必须导入为新的固定来源版本。已创建制作继续使用其固定的流程版本和工作区；
不得通过就地替换 vendor 源码改变未完成任务的阶段语义。
